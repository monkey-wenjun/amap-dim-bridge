# 高德导航投屏到仪表盘 —— 完整链路与证据（2026-10-02，CS11）

## 1. 仪表这侧

`/system/framework/ecarx.adapterapi.jar`（boot classpath，第三方 App 直接可见）里有：

```
com.ecarx.xui.adaptapi.diminteraction.DimInteraction
  create(Context)
  getMediaInteraction() / getNaviInteraction() / getPhoneCallInteraction()
  getContactsInteraction() / getVrInteraction()

com.ecarx.xui.adaptapi.diminteraction.INaviInteraction
  notifyTurnByTurnStarted() / notifyTurnByTurnStopped()
  updateTurnByTurnArrow(int|Bitmap)
  updateNextGuidancePointName(String)
  updateDistanceToNextGuidancePoint(int)   米
  updateDistanceToDestination(int)         米
  updateETA(int)
  updateDriveDirection(int)                这个版本是空实现
  notifyDestinationReached(String,int|Bitmap)
```

`NaviInteractionImpl` 内部维护一个 `Turn` 对象，每个 setter 改字段 + 设 `turnState`，
然后 `mNavigationDI.turnByTurn(mTurn)`：

| 调用 | turnState |
| --- | --- |
| notifyTurnByTurnStarted | 0 |
| updateTurnByTurnArrow / updateDistanceTo* / updateETA / updateNextGuidancePointName | 1 |
| notifyDestinationReached | 2 |
| notifyTurnByTurnStopped | 3 |

服务端 `com.ecarx.dim_interaction.server.dim_interaction.NavigationDimInteraction.turnByTurn()`：

```
log(arrow2, streetName3, distance5, timeEstimated7, nameOfSource8, distanceToNextGuidance9)
if (turn == null) throw "Turn object can not be null."
if (turn.getTurnState() == 0) throw "Navigation state is not correct."    <-- 坑
state 1 -> 组包 -> DimScreenUpdateData -> FrameBuilder
state 2 -> 组包 + 起一个延迟线程
state 3 -> dropNavigationScreen()
```

**所以：只推 turnState=1 的更新帧，退出时发 state=3。不要发 state=0。**

## 2. 高德这侧

高德车机版（`com.autonavi.amapauto`）会持续广播标准协议：

- action `AUTONAVI_STANDARD_BROADCAST_SEND`（普通广播，第三方 App 能收）
- `KEY_TYPE=10001` = 导航信息帧，字段（实测全量）：
  `ICON` / `NEW_ICON` / `CUR_ROAD_NAME` / `NEXT_ROAD_NAME` / `NEXT_NEXT_ROAD_NAME` /
  `SEG_REMAIN_DIS`(米) / `NEXT_SEG_REMAIN_DIS` / `ROUTE_REMAIN_DIS`(米) /
  `ROUTE_REMAIN_TIME`(秒) / `ETA_TEXT` / `SEG_REMAIN_TIME` / `CAR_DIRECTION` /
  `TRAFFIC_LIGHT_NUM` / `routeRemainTrafficLightNum` / `CAMERA_DIST` / `LIMITED_SPEED` /
  `CUR_SPEED` / `ROAD_TYPE` / `endPOIName` / `ROUTE_REMAIN_DIS_AUTO` ...
- `KEY_TYPE=10019` = App 状态/心跳类，`EXTRA_STATE` 是几十到几百的状态码（不是前台/后台枚举），
  本桥不依赖它
- `KEY_TYPE=10046` = 心跳；另有 12xxx / 13xxx / 60xxx 若干
- 退出导航后 `10001` 会停发（实测 40s 内衰减到 0），所以用「20 秒没有 10001」当导航结束的兜底

广播里的 `ICON` = 高德自带资源 `navistate_landback_<十六进制 id>.png`，见 `图标码表.md`。

车机里**已经在听**这个广播的还有：`ecarx.voiceservice`(XCVoiceService)、`net.easyconn`
（`QZ_EasyConnected.apk` 手机互联）、`com.baidu.che.codriver`（DuerOS，用 `AmapReceiverWrapper`
取状态/家和公司地址并反向控制高德）。它们都**不**把高德导航推给仪表 —— 推仪表那条只有原厂百度地图在做。

## 3. 复现步骤（调试用）

```bash

# 退出导航
adb shell am start -a android.intent.action.VIEW -d "androidauto://naviExit"

adb logcat -s AmapDimBridge DimNavi NavigationDimInteraction FrameBuilder FrameSender
```

## 4. 默认地图 / 卸百度地图（未完成，卡在没 root）

- `pm uninstall com.baidu.naviauto` -> `Failure`（预装应用删不掉）
- `pm disable / disable-user` -> 被 OEM 直接 `Killed`（EXIT=137），这条被车机挡死了
- **`pm block com.baidu.naviauto` 可用**（EXIT=0，`blocked=true`）：屏蔽后百度地图
  完全起不来（`monkey` 报 no activities、进程 0），`pm unblock` 可完整还原。
  但副作用：车机语音「导航去X」是**硬绑百度**的（DuerOS 默认导航 = Baidu），
  屏蔽后语音导航直接失败（`Unable to start service Intent { act=com.baidu.NaviControllerService
  pkg=com.baidu.naviauto } not found`），不会自动切高德。

- 默认导航应用的开关在 DuerOS 私有偏好里：
  `SharedPreferences prefs_amap / key_default_navi_app`，值取枚举
  `com.baidu.che.codriver.common.d`（`Baidu` / `Amap_Lite` / `Amap`）。
  设置入口是 DuerOS 开放 SDK 的命令 **`fun_navi_set_default_app`**，
  服务端实现就是 `new NaviPreferences().saveDefaultNaviApp(NaviApp.valueOf(data))`
  （data 直接就是字符串 `"Amap"`）。
  SDK 客户端库 `com.baidu.che.codriversdk` 现成地内嵌在
  `/system/app/XCVoiceService.apk` 里（`CdNaviManager` + `RequestManager` + `PlatformService`，
  走 bindService/AIDL `com.baidu.che.codriver.ICoDriverService`，接口是混淆过的）。

  要改这个偏好只有两条路：
  1. **不用 root**：把 `com.baidu.che.codriversdk` 的 dex 抽出来，像 `cmaprobe` 用
     `DexClassLoader` 加载 CMA API 那样，在 App 里初始化 SDK 并调 `CdNaviManager` 的
     map.tool 请求发 `fun_navi_set_default_app`（值 `Amap`）。
     不确定点：DuerOS 可能只认注册过的包名（`app_controler.register`）。
  2. **root 车机**后直接改 `/data/data/com.baidu.che.codriver/shared_prefs/prefs_amap.xml`。

  在选定方案前，**百度地图保持原样（未屏蔽）**，避免把语音导航弄挂。

## 5. 其它备忘

- 高德车机版 V9.1.0.600087（arm32）在 4.4.3 上能装能跑（`MainMapActivity` 正常渲染）；
  APK 签名 `CN=minimap, O=autonavi`（官方），sha256
  `2418635818cd3e3294cfaa66a1fcb2d94d3a903dee81956e399a960e67f07d9f`。
- V9.5.0.600013 是 arm64，本车（i.MX6 / Cortex-A9 armv7）装不了。
- 高德自己认的 URI scheme 只有 `androidauto://`，host 有 `navi` / `naviPreview` /
  `keywordNavi` / `viewGeo` / `viewReGeo` / `naviExit` / `naviSetting` 等。
- 用 `am startservice -n com.baidu.che.codriver/com.baidu.che.codriver.sdk.CoDriverService
  --es query "..."` 可以给 DuerOS 下**文本指令**（调试语音流程很方便）。
